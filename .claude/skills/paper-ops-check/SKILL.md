# paper-ops-check — 모의투자 운영 점검

이 스킬은 **지금 돌고 있는 시스템이 건강한가**를 확인한다. 모든 점검은 앱이
`localhost:8080`에 떠 있어야 가능하다. 앱이 꺼져 있으면 "점검 불가"로 적는다 —
추정으로 통과 표시하지 않는다.

## 안전 원칙 — 먼저 읽는다

- **돈이 실제로 움직이는 조작(주문 실행, 강제청산 실행)은 대신 눌러주지 않는다.**
  명령과 확인 방법을 안내하고 **사용자가 직접 실행**하게 한다. 모의투자 계좌라도
  같다 — 조작 권한의 경계를 흐리면 나중에 실전에서 사고가 난다
- 운영 중인 앱의 설정(paper 기본값, 리스크 룰, 지갑 칸)을 점검 중에 바꾸지 않는다

## 1. 기본 상태 점검

| 확인 | 방법 | 정상 |
|---|---|---|
| 앱 살아있음 | 대시보드 `http://localhost:8080` | 화면이 뜸 |
| 운전 상태 | 대시보드 control 카드 | RUNNING |
| 연속 가동일 | `GET /api/trading/run-streak` | 숫자가 매 거래일 +1 |
| 매매 기록 | 대시보드 + 텔레그램 알림 이력 | 체결/에러/청산 알림 도달 |

상태가 **SAFE_MODE**(새로 사는 건 멈추고 이미 산 것만 지키는 상태)면 그 자체가
고장은 아니다. 왜 들어갔는지가 중요하다 — 보통 KIS API 장애나 하트비트 끊김이다.
연결이 회복되면 자동으로 RUNNING으로 돌아온다.

## 2. 재가동 규칙 (중요)

멈춘 앱을 다시 돌릴 때 **`/start`로 바로 전환하지 않는다.**
반드시 재가동 게이트를 거친다:

```
POST /api/trading/resume
```

이유: 기동 시 재동기화(내가 지금 뭘 들고 있는지 실제 계좌와 맞추기)를 건너뛰면
장부와 실제가 어긋난 채로 매매가 시작된다.

## 3. 릴리즈 갭 3종 — 이 프로젝트에 남은 관문

### 3-1. 강제청산 리허설 (⚠ 미실행)

강제청산 코드는 다 됐지만 **모의계좌에서 한 번도 실제로 눌러본 적이 없다.**
한 번 성공해야 Gate 2가 완료로 판정된다.

```
POST /api/trading/liquidation-drill
```

절차 안내 시 반드시 함께 알린다:
1. 장중에, 보유 포지션이 있을 때 해야 의미가 있다
2. 실행 후 확인할 것 — 전량 매도 주문 접수 / 미체결 취소 / 텔레그램 청산 알림
3. **사용자가 직접 실행한다.** 결과를 함께 확인하고 기록한다

### 3-2. 연속 5거래일 무중단 가동 (☐ 진행 중)

```
GET /api/trading/run-streak
```

- 기록은 거래일 15:25에 자동으로 남는다 — 그 시각에 앱이 꺼져 있으면 그날은 기록 없음
- 5일이 될 때까지 매일 확인하고, 끊기면 **왜 끊겼는지**를 함께 적는다
  (끊긴 이유를 모르면 5일을 다시 채워도 같은 이유로 또 끊긴다)

### 3-3. 연속손실 집계 단위 (⚠ 잔존 결함)

지금은 매도 **체결 조각(청크)** 단위로 연속 손실을 센다. R 사이징으로 여러 주를
파는 일이 생기면서, 한 번의 매매가 여러 조각으로 나뉘어 손실 3회로 잘못 셀 수 있다.
**라운드트립(사고-팔고 한 바퀴) 단위 집계로 바꿔야 한다.** 점검 시 이 항목의
현재 상태를 함께 보고한다.

## 4. 타임컷·스케줄 점검

| 항목 | 시각(KST) | 확인 |
|---|---|---|
| 매매 루프 | 장중 1초, 종목 라운드로빈 | 종목 수만큼 간격이 벌어지는 게 정상 |
| 신규 매수 금지 | 15:20 이후 | `MarketCloseRule` |
| 보유분 전량 매도 | 15:15 | `TimeCutScheduler` |
| 가동일 기록 | 15:25 | `RunStreakRecorder` |

**주의:** 15:15에 앱이 꺼져 있으면 그날 타임컷은 건너뛴다 — 포지션이 다음 날로
넘어간다. 장 마감 무렵 앱을 끄는 것은 위험하다.

## 5. 점검 보고 형식

```
[운영 점검] 2026-07-22 14:30 KST
| 항목 | 상태 | 근거 |
|---|---|---|
| 앱 | 살아있음 | 대시보드 응답 |
| 운전 | RUNNING | control 카드 |
| 연속 가동일 | 2일 | GET /run-streak |
| 청산 리허설 | 미실행 | 실행 기록 없음 |
| 오늘 체결 | 매수 1건 (005930, 3주) | 텔레그램 + 대시보드 |
→ 남은 관문: 리허설 1회 · 가동일 3일 더
```

## 6. 사용자에게 설명할 때

이 프로젝트 규칙: **10살 아이에게 설명하듯** 쓴다.

- 영어·전문용어를 그대로 쓰지 않는다. 꼭 필요하면 뜻을 괄호로 붙인다
  - SAFE_MODE → "SAFE_MODE(새로 사는 건 멈추고 지키기만 하는 상태)"
  - 데드맨 스위치 → "데드맨 스위치(사람이 살아있는지 주기적으로 확인하는 장치)"
- 결론을 한 줄로 먼저, 그다음 쉬운 설명
- 숫자를 물으면 "몇 건 샀고 얼마 벌었다/잃었다"처럼 결과 위주로 답한다

## 7. 장애가 났을 때

`docs/OPERATIONS.md`가 장애 대응·재가동 절차의 원문이다. 이 스킬과 내용이
어긋나면 **`docs/OPERATIONS.md`가 우선**이고, 어긋난 사실을 사용자에게 알린다.
