# 백테스트 인프라 설계 — Phase 3의 전제 조건

> 이 프로젝트의 원칙 ②는 "백테스트 없는 규칙은 채택하지 않는다"이고,
> [성과 거버넌스](PERFORMANCE-GOVERNANCE.md)는 "백테스트 기준선 대비 괴리"로 강등을
> 판정한다. 즉 **백테스트 엔진 없이는 원칙도 거버넌스도 실행 불가능하다.**
> 이 문서는 그 인프라의 요구사항·설계·합격 기준을 정의한다.
>
> ⚠️ 현행 `VolatilityBreakoutStrategy(K=0.5)`도 검증된 적이 없다. 엔진이 완성되면
> **가장 먼저 현행 전략을 소급 검증**한다 — 지금의 K=0.5는 관례값이지 근거값이 아니다.

---

## 1. 요구사항 — 좋은 백테스트의 4조건

| 조건 | 의미 | 이 시스템에서의 구현 |
|---|---|---|
| **동일 코드** | 백테스트와 실전이 같은 전략 코드를 실행해야 함 (재구현하면 미묘하게 달라짐) | `Strategy`·`RiskRule` 인터페이스를 그대로 사용 — 기존 인터페이스 분리 설계가 이미 이를 지원 ✅ |
| **선견 편향 금지** | 그 시점에 알 수 없던 정보(미래 데이터)를 쓰지 않음 | §3.2 이벤트 타임스탬프 정합 |
| **비용 포함** | 수수료·세금·슬리피지 반영 없는 백테스트는 환상 | §2.3 체결 모델 |
| **충분한 표본** | 소표본 통계는 노이즈 | §4 합격 기준 (최소 트레이드 수) |

## 2. 엔진 설계

### 2.1 아키텍처 — 구현체 교체 방식

```
@Profile("backtest")
  BacktestMarketDataService  : DB 적재 과거 캔들을 시간 순서대로 재생
  BacktestOrderClient        : 가상 체결 (§2.3 체결 모델)
  BacktestPositionManager    : 인메모리 계좌 (현금 포함 — F-1 교정 반영)

BacktestRunner: 가상 시계를 1틱씩 전진시키며 기존
  Strategy → Signal → RiskEngine → OrderEngine 파이프라인을 그대로 통과시킴
```

- 핵심: **RiskEngine을 우회하지 않는다.** 리스크 룰까지 포함해야 "시스템 전체"의
  백테스트가 되고, 실전-백테스트 괴리 판정의 분모로 쓸 수 있다.
- `LocalTime.now()` 같은 실시간 의존은 `Clock` 주입으로 치환 (감사 F-8과 동일 작업 —
  백테스트가 이 리팩터를 강제한다).

### 2.2 데이터 적재

| 항목 | 설계 |
|---|---|
| 소스 | KIS 일봉/분봉 API (수정주가 `FID_ORG_ADJ_PRC=1` — 현행과 동일) |
| 저장 | 로컬 DB `candle_history` 테이블 — 야간 배치로 워치리스트 종목 적재 |
| 분봉 필요성 | 현행 전략은 "당일 현재가 > 돌파가" 판정이므로 **일봉만으로는 진입 시점을 모른다** (종가가 돌파가 위여도 장중 언제 돌파했는지 불명). 분봉(최소 10분봉)으로 돌파 시각과 진입가를 재현 |
| 생존 편향 | 상장폐지 종목이 빠진 데이터는 성과를 부풀린다. v1 유니버스(대형주)에서는 영향이 작으므로 **한계로 명시하고 수용**, 유니버스 확대 시(Phase 4) 재평가 |
| 기간 | 최소 3년 (상승장·하락장·횡보장을 모두 포함해야 레짐 편향 방지) |

### 2.3 가상 체결 모델 (보수적으로)

```
진입가   = 신호 발생 다음 분봉의 시가          (신호 본 그 가격에 체결됐다고 가정하지 않음)
슬리피지 = 진입가 × 0.1% × 양방향 (초기 가정값) → 실전 실측값으로 교체
비용     = 위탁수수료 + 거래세 (거버넌스 §1의 비용 상수 공유)
매도     = 타임컷/손절 동일 규칙 — 하한가 등 체결 불가 상황은 다음 봉 시가로 지연 체결
```

**왕복 총비용(슬리피지+수수료+세금 합계)은 0.3~0.5% 미만으로 잡지 않는다.**
단타 전략의 사인(死因) 1순위가 거래 비용이며, 비용 가정이 낙관적인 백테스트의
우상향 곡선은 실전에서 우하향으로 뒤집힌다. 비용을 이 수준으로 잡고도 PF가 기준을
넘는 전략만이 실전 후보 자격이 있다.

원칙: **애매하면 항상 불리하게.** 백테스트가 낙관적이면 실전에서 반드시 실망하고,
보수적이면 실전이 서프라이즈가 된다 — 후자가 생존에 유리하다.

## 3. 검증 절차 — 과최적화를 걸러내는 순서

### 3.1 Walk-Forward 검증 (파라미터 튜닝 시 필수)

```
|-- 학습 6개월 --|-- 검증 3개월 --|
        |-- 학습 6개월 --|-- 검증 3개월 --|   ← 3개월씩 밀며 반복
```

- 파라미터(K값 등)는 학습 구간에서만 정하고, 성과는 **검증 구간만** 집계한다.
- **민감도 검사**: K=0.4 / 0.5 / 0.6 성과가 급변하면 불합격 — 좋은 전략은 파라미터
  근방에서 성과가 완만하다. 뾰족한 최적점은 과최적화의 지문이다.

### 3.2 이벤트 백테스트 (Phase 3c 용)

- 이벤트(공시·뉴스) 타임스탬프와 캔들 타임스탬프의 정합이 생명:
  **"그 시점에 알 수 있었는가"** — 장 마감 후 공시를 당일 진입으로 계산하면 선견 편향.
  규칙: 이벤트 발생 시각 + 처리 지연(수집 주기 30분) 이후의 첫 봉부터 진입 가능.
- 이벤트 유형별 D+1~D+20 수익률 분포를 산출 → 평균이 아니라 **중앙값과 하위 25%**를
  기대수익으로 채택 (평균은 소수 대박이 왜곡).

### 3.3 필터 A/B 검증 — 스위치는 만들되, 켜는 건 이긴 다음

실무에서 통용되는 아래 4개 필터는 Phase 2에서 **코드 훅(설정 스위치)으로 구현하되
기본 OFF**로 두고, B-3에서 순정(필터 없음) 대비 A/B로 검증해 이기는 조합만 ON으로
전환한다. 원칙 ②는 필터에도 예외 없이 적용된다 — 파라미터 추가는 곧 과최적화 위험
추가이므로, 아무리 상식적인 필터라도 관문을 거친다:

| 필터 | 가설 | 파라미터 후보 |
|---|---|---|
| 진입 시간 창 | 장초반(09:00~09:15) 휩소성 가짜 돌파 회피 | 09:10 / 09:15 / 09:30 이후만 진입 |
| 거래량 확인 | 거래량이 동반된 돌파만 신뢰도가 높다 | 돌파 시점 누적 거래량 ≥ 전일 동시간대 × 1.5~3.0 |
| 트레일링 스톱 | 오후 흘러내림에서 수익 보존 (타임컷 보완) | +3% 도달 후 고점 대비 1~2% 하락 시 청산 |
| 지수 레짐 | 지수 급락일의 개별 돌파는 무너지기 쉽다 | KOSPI가 당일 시가 아래면 신규 진입 금지 |

**채택 판정**: 필터 적용 버전이 순정 대비 **검증 구간의 PF와 MDD 양쪽에서 우위**일
때만 ON. 한쪽만 개선되면(수익↑ MDD↑ 등) 채택 보류하고 결과만 기록한다.
조합 탐색은 단일 필터 → 상위 2개 조합까지만 (조합 폭발 = 과최적화 지름길).

### 3.4 최종 관문 — 모의투자 (이미 인프라 보유)

백테스트 통과 → 모의투자 30건 이상 → 실전 축소 자금. 이 3단 관문은
[거버넌스 §5](PERFORMANCE-GOVERNANCE.md)의 승격 절차와 동일한 사다리를 공유한다.

## 4. 합격 기준 (백테스트 → 모의 승격)

| 지표 | 기준 | 이유 |
|---|---|---|
| 트레이드 수 | ≥ 100건 | 소표본 차단 (거버넌스 §2와 일관) |
| Profit Factor | ≥ 1.3 (비용 차감 후) | 1.0 근처는 비용 오차로 뒤집힘 |
| 기대값 | > 0 (검증 구간만, Walk-Forward) | 학습 구간 성과는 채점 대상 아님 |
| MDD | 백테스트 MDD ≤ 15% | 실전은 통상 이보다 나쁘다 — 거버넌스의 1.5배 룰 분모 |
| 민감도 | 인접 파라미터에서 PF ≥ 1.15 유지 | 과최적화 지문 검사 |

합격한 전략의 **기대값·PF·MDD를 설정 파일로 버전 관리**한다 — 이것이 거버넌스가
요구하는 "백테스트 기준선"이며, 실전 괴리 판정의 분모가 된다.

## 6. v1 구현 노트 (2026-07-10 — 일봉 근사)

B-1~B-3은 `com.trading.backtest` 패키지로 구현됐다 (`--spring.profiles.active=backtest`,
전용 `backtest-db` 사용 — 라이브 DB 무오염). §2.2의 분봉 요구는 **KIS가 과거 분봉을
소급 제공하지 않아** v1에서 일봉 근사로 대체했고, 대신 `MinuteCandleCollector`가
매일 15:40 당일 분봉을 축적해 미래의 정밀 재검증을 준비한다.

**일봉 근사 관례 (전부 보수 방향, §2.3 원칙 준수):**

| 항목 | v1 관례 |
|---|---|
| 진입 시각 | 10:00 고정 체크포인트 (돌파 시각 불명) |
| 진입가 | 이분탐색으로 복원한 돌파 크로싱가 + 슬리피지 0.1% — 전략 `evaluate()`의 가격 단조성만 이용, K 로직 미복제 (동일 코드 원칙) |
| 당일 진입 후 손절 | 저가 ≤ 손절가면 체결 간주 (저가가 진입 전이었을 가능성 무시 — 비관) |
| 타임컷 체결가 | 당일 종가 근사 |
| 비용 | 왕복 ≈0.41% (슬리피지 0.1%×2 + 수수료 0.015%×2 + 매도 제세 0.18%) |

**§3.3 필터 구현 상태:** 4종 모두 스위치(기본 OFF, `trading.filters.*`)로 구현.
트레일링 스톱·지수 레짐(갭다운 변형)은 일봉 A/B 가능 — B-3 리포트에 포함.
**진입 시간창·거래량 확인은 돌파 시각이 필요해 일봉으로 검증 불가** — 분봉 축적 후
별도 세션에서 A/B 전까지 켜지 않는다 (원칙 ②).

산출물: `logs/backtest/REPORT-*.md` (실행 리포트), 합격 시 `docs/BACKTEST-BASELINE.yml`
(거버넌스 기준선 — 버전 관리).

## 7. B-3 판정 결과 (2026-07-11 실행) — ❌ 불합격

기간 2023-07-11~2026-07-10, 대형주 6종목(005930·000660·373220·005380·035420·068270),
왕복 비용 0.41%, Walk-Forward 10윈도우 (REPORT-20260711-1131.md):

- **검증 구간 집계: PF 0.66, 기대값 -0.333%, MDD 50.4%** (합격선: PF≥1.3, 기대값>0, MDD≤15%)
- 10개 검증 윈도우 **전부 PF < 1.0** (최고 0.98) — 특정 구간의 불운이 아니라 구조적 열세
- K 민감도: 0.4/0.5/0.6 전기간 PF 0.57/0.52/0.53 — K 튜닝으로 구제 불가
- 필터: 트레일링 스톱 1%가 PF 0.66→0.71, MDD 50.4→44.3%로 동반 개선하나
  **PF < 1.0인 전략은 필터로 흑자 전환되지 않는다** — 채택 보류
- ~~지수 레짐(갭다운 금지)은 개선 없음 → 기각~~ ⚠️ **이 판정은 무효 (2026-07-25 확인, §14.4)**:
  `BacktestRunner`가 `loadSeries(config.symbols(), …)`로 **매매 대상 종목만** 메모리에 올리는데
  KOSPI는 그 목록에 없어 `dayBar("KOSPI")`가 항상 null → `isBearishRegime()`이 항상 `empty` →
  `IndexRegimeRule`은 켜도 **항상 통과**했다. git 이력상 B-3 최초 실행부터 줄곧 무발동이므로
  "개선 없음"은 필터가 켜진 적 없는 상태의 관측이다. paper는 이 필터를 켠 적이 없어 실계좌
  영향은 없다. 재판정하려면 지수를 리포지토리에서 직접 읽어야 한다(§14.4의 `IndexTrendRule` 방식).

**결론: 현행 "당일 변동성 돌파(대형주·일봉·왕복 0.41%)"는 비용 차감 후 음의
기대값이 3년 전 구간에서 일관되게 확인됐다. 원칙 ②에 따라 이 전략은 실전 승격
불가이며, Phase 3(이벤트 드리븐) 착수 전 전략 교체/재설계 판단이 필요하다.**

남은 검증 여지 (기각 전 확인할 것): ① 진입 시간창·거래량 필터 — 돌파 전략의

## 10. 테마 파급(Spillover) 통계 — B-4 확장 (2026-07-14, 실행 대기)

사용자의 실제 투자 가설 — "반도체 호황 같은 섹터 호재가 뜨면 장비·소재 납품업체가

§8의 자기 이벤트 통계(종목 X의 공시 → X의 수익률)와 달리, **앵커 대형주의 공시 →
같은 테마 밸류체인 종목들의 D+N 초과수익**을 잰다 (customer-supplier momentum 계열).

- 표본 구조: `backtest.event-themes`의 `<테마>-anchor` / `<테마>-chain` 키 쌍.
  파일럿은 반도체 (앵커: 삼성전자·SK하이닉스, 체인: 장비·소재·부품 19종목).

  유효 표본을 뻥튀기)을 설계 단계에서 차단. 이벤트당 커버리지 3종목 미만은 제외.

## 11. 진입 트리거 실험 — "언제 타는가" 격리 비교 (2026-07-14, 실행 대기)

§10이 "무엇이 오르는가"(어떤 앵커 이벤트가 파급되는가)를 재면, 여기서는 같은
이벤트 표본에서 **진입 방식만 바꿔** 성과 차이를 잰다 (`EntryTriggerBacktester`).
사용자 가설의 후반부 — "관련주를 상승 반등 신호에 탄다" — 의 검증 장치.

- 트리거 3종: **IMMEDIATE**(공시 다음날 시가 — §10과 동일 기준선) /
  **PULLBACK_REBOUND**(눌림 후 눌림일 고가 돌파 — "상승 반등") /
  **BREAKOUT**(이벤트일 고가 돌파 — 모멘텀 확인).
- 공정 비교: 청산은 전 트리거 공통 **이벤트 D+10 종가** 고정 — 진입 타이밍만
  변수로 격리. 트리거가 D+5까지 완성 안 되면 미발동 → **발동률**로 별도 집계
  (기회 빈도 자체가 트리거의 속성 — 발동률이 너무 낮으면 통계가 좋아도 못 쓴다).
- v1은 일봉 근사: 돌파 진입가 = max(시가, 기준가) 보수 추정, 같은 봉의 눌림·반등
  동시 발생은 다음 봉으로 미룸. **분봉 축적 후 분봉 정밀 버전으로 재검증이 전제** —
  v1 결과만으로 실전 트리거를 확정하지 않는다.
- 표본 규약은 §10과 동일 (횡단면 중앙값 접기·커버리지 3·시장별 벤치마크).
  클러스터 병합만 순수 시간 기준이라 표본 수가 §10과 소폭 다를 수 있다.
- 산출: 리포트 "진입 트리거 실험" 섹션 (테마×유형×트리거별 표본·발동률·승률·
  중앙값·p25). **레지스트리에는 쓰지 않는다** — 실험이지 유형 통계가 아니다.
- 판정 지침: 어떤 트리거가 IMMEDIATE 대비 중앙값 우위 + 발동률이 실용 수준이면
  분봉 정밀 검증 → 전략화(Phase 3d) 후보. IMMEDIATE가 최강이면 "확인 후 진입해도
  늦지 않다"는 §10 해석이 강화되는 것이고, 전부 음(-)이면 §8 결론(공시 확인 후
  진입은 늦다)이 파급 경로에도 성립한다는 뜻이다.
- 실행: `--backtest.mode=events`에서 §10과 함께 산출 (DART_API_KEY 대기).

## 14. Exit Lab / Risk Lab — 손익비 재설계(다일 보유) (2026-07-22) — 엣지 실재 → 리스크 축소로 첫 §4 통과 후보(§14.1)

§13에서 스캘핑이 승률 59.8%인데도 최악(PF 0.33)이라는 진단 — **손익비(평균이익÷평균
손실)가 거꾸로** — 을 출발점으로, 진입 로직은 고정한 채 출구만 재설계해 손익비를
바로잡을 수 있는지 측정했다. `--backtest.mode=exit-lab`(`BacktestOrchestrator`)로 VB·MA
진입 각각에 5개 출구 프로필(P0 기준선 / P1 타이트·당일 / P2 다일·느슨트레일 / P3
다일·조인트레일 / P4 다일·순수손절)을 Walk-Forward 스윕했다. 신규 인프라:
`ExitLabProperties`(타임컷 토글·최대보유일), `BacktestRunner` 다일 이월·최대보유일
강제청산, `BacktestMetrics`에 손익비(payoff)·평균보유일 추가.

**중대한 낙관 편향 발견·수정 (검증의 핵심)** — 1차 실행은 화려했으나(6종목 MA P2 PF 3.78·
MDD 3.7%) **일봉 근사의 낙관** 때문이었다: 이월 포지션의 트레일 청산이 밤사이 갭으로
손절 레벨을 관통해도 레벨가로 체결됐다(실제로는 더 나쁜 시가 체결). `DailyBarSimulator.
checkTrailingStop`을 `checkCarriedStop`과 동일한 보수 모델로 수정 — 어제까지 고점으로
레벨을 먼저 정하고(선견 차단), **시가 ≤ 레벨이면 시가 체결(갭 관통), 저가 ≤ 레벨이면
레벨 체결**. 수정 후 MDD가 대략 2~3배로 뛰며 1차의 화려함이 사라졌다 — 낙관이 특히

1. **손익비 재설계는 작동한다.** 당일 청산(P0·P1)은 두 진입 모두 손익비 ~1.0·PF<0.7. 다일

   짧게 끊고 이익을 추세로 태운다"가 정량 확인됐다. 트레일 없는 P4가 약한 걸 보면 **트레일링이

**결론**: 손익비 뒤집기(다일 트레일링 + 정배열 진입) 방향은 **실재하는 양(+) 기대값 엣지로
검증됐다**(넓은 유니버스·수백 건에서 재현). 남은 벽은 **MDD 21% > 15%** 하나다. 이는
"기준 완화" 사안이 아니라 **리스크 축소로 기준을 충족시키는** 공학 문제다 — 다음 지렛대:
ⓐ 포지션 사이징 축소(1R을 계좌 1%→0.5%로) ⓑ 동시 보유 종목/포트폴리오 히트 상한 ⓒ 지수
레짐 필터(지수가 추세 아래면 신규 진입 금지 — `FilterProperties.IndexRegime` 훅 존재).
셋 다 MDD를 직접 겨냥하며 엣지(기대값)는 보존한다. 이후 ⓓ 왕복 비용 상향 민감도 → ⓔ
분봉 정밀 재검증이 남는다.

**거버넌스·게이트**: Exit Lab 자체는 **거버넌스 기준선을 쓰지 않는다**(`writeExitLabReport`

### 14.5 기준선 정본화 + 커버리지 관문 (2026-08-17) — §14.1 앵커 드리프트 사고의 구조적 해소

**① 회귀 앵커 정본화 — 문서는 더 이상 앵커가 아니다.**

  창이 다르면 대조 자체를 생략한다. 기준선 파일이 없으면 조용히 건너뛴다(첫 기록).

**② 커버리지 관문 — 데이터가 모자라면 채점을 시작하지 않는다.**
백필 7일 슬랙은 목적(불필요한 API 호출 억제)이 유효하므로 유지하되, **고정 판정 창의 끝만 예외**로

확인한다.
- `write-baseline=true` 실행은 미달 시 **예외로 중단**(오염된 기준선이 굳는 것이 최악이므로),
  그 외는 경고 + 리포트 기재.
- 거래일 판정은 `MarketCalendarService`를 쓰되 **꼬리 지연만** 본다(구간 안쪽 구멍은 미검사 —
  캘린더에 없는 임시 휴장일 때문에 헛경보가 난다). 실측 확인: 주말·성탄절·연말 휴장을 결측에서 정확히 제외.

**검증**(`_workspace/8_impl`·`9_audit`·`10_verify_anchor-sot-and-coverage.md`): 테스트 543/543 통과 ·

## 15. 진입 교체 트랙 — 돈치안 돌파 / RSI(2) 평균회귀 (2026-08-03) — ⚠ 돈치안 조건부 통과, RSI 열위

§13에서 paper의 3방식이 전부 불합격하자, **진입 로직을 외부에서 검증된 고전 기법으로 교체**해
§14가 확립한 검증 경로(출구=P3 다일 트레일링, 사이징 스윕, 약세장 창, 지수 추세 필터)에 그대로
태워 비교했다. 대체 대상과 후보:

| 대체 대상 | 새 진입 | 구현 |
|---|---|---|
| 전략1 = VB(당일 변동성 돌파) | **돈치안 채널 돌파** — 직전 20일 고가 상향 돌파 + 종가>MA120 | `DonchianBreakoutStrategy` |
| 전략3 = 눌림목 스캘핑 | **RSI(2) 평균회귀** — 종가>MA120 추세 안에서 RSI(2)<10 과매도 | `RsiMeanReversionStrategy` + `RsiCalculator` |

두 전략 모두 `Signal`만 반환하고(흐름 규칙 준수), 출구는 프레임워크(ATR 손절·트레일링·최대보유)가
맡는다. 기본 OFF(`trading.donchian.enabled` / `trading.rsi.enabled`) — 백테스트에서만 orchestrator가 켠다.

**⚠ RSI(2)는 시뮬레이터에 새 진입 경로가 필요했다 (근사 가정 추가).** 기존 `DailyBarSimulator`의
진입은 *돌파 전용*이다 — 당일 고가에서 발화 여부를 보고 [시가, 고가] 이분탐색으로 돌파가를 복원한다.
평균회귀 신호는 **종가에 확정**되므로 이 경로로는 잡히지 않는다. 그래서 `checkMeanReversionEntry`를
신설해 시뮬 현재가를 당일 **종가**로 놓고 평가·진입한다(Connors 관례). 부수 효과:
당일 진입분은 종가 매수라 **당일 손절·당일 트레일 판정을 하지 않는다**(장중 저가/고가는 진입 전에
성립하므로 적용하면 선견편향). 이월분 트레일은 진입 전에 먼저 처리한다. 돈치안은 기존 돌파 경로 그대로다.

**PF·기대값은 5점 전부 완만**(1.84~1.95 / +1.26~1.36%)한데 **MDD는 96 나쁨→120 통과→144 좋음→
168 나쁨→192 좋음으로 요동**친다. 144가 평지 위가 아니라, **0.5R에서의 MDD 잣대 자체가 특정
에피소드(어느 종목이 하필 그 주에 추세 위였는가)에 좌우되는 경로 의존 노이즈**라는 뜻이다 —
§15.4의 비단조 경고가 파라미터 축에서도 재확인됐다. 따라서 이 지도로 추세 기간을 "고르지" 않는다
(120 유지). 낙폭 잣대를 의미 있게 만들려면 먼저 사이징으로 분포 전체를 한도에서 멀리 떼어놓아야 한다.

**종합**: 엣지는 모든 축에서 강건, 낙폭만 0.5R에서 노이즈 — **다음 검증은 SZ2(0.25R·동시5)로
재고정한 뒤 §15.3(파라미터 ±20%)·§15.4(비용 0.41→0.80%)를 재실행**해 전 축 여유 통과를 확인하는
것. 통과 시 §15.5의 후보 프로필을 SZ2로 갱신한다(측정이며 채택 아님 — 이후에도 실측 슬리피지·
ADR-001·G2 관문은 그대로).

### 15.7 SZ2(0.25R) 고정 재시험 (2026-08-04) — 두 관문 모두 전 항목 통과, 병목이 사이징이었음이 확인됨

§15.6의 결론(엣지는 강건, 낙폭만 한도 근처에서 노이즈)을 따라 사이징을 **SZ2(0.25R·동시5)** 로
고정하고 §15.3(파라미터 ±20%)·§15.4(비용)를 재실행했다. 나머지 조건은 동일(약세장 24창, 지수 MA120 ON).
**회귀 앵커 D0·C0가 §15.6 SZ2(1181건 / PF 1.92 / 기대값 +1.340% / MDD 4.20%)를 정확히 재현** — 실행 유효.

대가는 복리 축소(6.5년 총수익 +358% → +115%)이며, 이는 안전과 수익의 교환이라 **선택은 사람(G2)** 이다.

**여전히 실전 후보가 아닌 이유**: 생존편향(2020~2022 상장폐지 0건, 일부 후보는 당시 미상장) ·
일봉 근사 · 지수는 KOSPI 단일 · 크래시형 MDD(2024-08-05류)는 이 필터로 못 막음 · **비용 가정의
실측 미완**(§16.3). 승격은 ADR-001(다일 보유) 재논의 + 게이트 G2 선행.

### 15.8 B동(당일 단타) 진입 조건 A/B (2026-08-04) — ❌ 구제 실패 + 거래량 필터 선견편향 발견

ADR-001 개정 결정 2("B동 유지, 진입 조건 강화")를 데이터로 판정하기 위해, VB 진입과
**현행 paper 출구**(ATR1.5 · 15:15 타임컷 · 트레일 arm3%/trail1%)·사이징(1.0R·동시5)을
그대로 고정하고 진입 필터만 스윕했다(`--backtest.mode=vb-filter-lab`, 약세장 24창).

| 프로필 | 트레이드 | PF | 기대값 | MDD | 총수익 | 판정 |
|---|---|---|---|---|---|---|
| B0 필터OFF (현행 B동) | 3955 | 0.80 | −0.164% | **82.3%** | **−78.45%** | ❌ |
| B1 지수 MA120 이탈 금지 | 3072 | 0.87 | −0.065% | 61.2% | −52.65% | ❌ |
| ~~B2 거래량 확인~~ | ~~5941~~ | ~~3.21~~ | ~~+1.812%~~ | ~~0.00%~~ | ~~+436,167,676%~~ | 🚫 **무효** |
| ~~B3 지수MA120+거래량~~ | ~~3930~~ | ~~3.61~~ | ~~+2.010%~~ | ~~0.00%~~ | ~~+7,850,720%~~ | 🚫 **무효** |

**B2·B3는 선견편향으로 무효다 (엔진 결함).** 거래량 필터 조건은
`today.volume() < yesterday.volume() × ratio`인데, 일봉 근사 엔진은 10:00 진입 판정 시점에
당일 캔들의 **하루치 총거래량**을 넘긴다(`DailyBarSimulator.firesAt`·`BacktestMarketDataService`
모두 `todayBar.volume()`). 즉 "그날 결국 거래가 터진 날"만 골라 사는 셈이라, 큰 상승일을
사후적으로 선택한다. 증상이 명백하다 — **필터를 켰는데 트레이드가 3955→5941로 늘고**(제약이
표본을 늘릴 수는 없다), 승률 37%→66%, MDD 0.00%, 1,000만원이 43조원이 됐다.

> 이 함정은 §6 v1 구현 노트에 이미 "시간창·거래량 필터는 분봉 축적 후 검증"으로 예고돼
> 있었다. 이유가 바로 이것이다 — **장중 누적 거래량을 알 수 없으면 거래량 필터는 정직하게
> 백테스트할 수 없다.** 분봉이 쌓이기 전까지 이 두 필터는 측정 대상이 아니다.

**유효한 판정은 B0·B1뿐이고, 둘 다 크게 불합격이다.** 현행 B동은 약세장 6.5년에서
**계좌를 −78% 만들고 최대낙폭 82%**를 냈다. 지수 추세 필터를 붙여도 −53%·61%로,
"덜 나쁜" 수준이지 수익 구조가 아니다(기대값이 여전히 음(−)).

**결론**: 진입 조건을 바꿔 B동을 구제하는 경로는 **현재 측정 가능한 범위에서 없다.**
ADR 개정안의 "B동 30% 존치"는 이 수치를 보고 재검토해야 한다 — 개정안 §2.2에서 계산한
"B동이 계좌 낙폭의 지배적 원인(7.5~18.4%p)"이 실측으로 확인됐고, 오히려 과소평가였다
(자체 MDD 82.3% × 30% = **계좌 기여 24.7%p**).

### 15.9 B동 재검토 — "유명한 기법이 왜 마이너스인가"의 답: 마찰 (2026-08-05)

사용자 문제 제기: *"이미 대중에게 유명한 기법인데 장이 좋을 때도 마이너스인 게 이해가 안 된다.
혹시 규칙·값을 잘못 넣었거나, 선물 거래를 전제로 한 기법 아닌가?"* — 셋 다 확인했다.

**① 구현은 정확하다.** `BreakoutCalculator`: `목표가 = 당일 시가 + (전일 고가 − 전일 저가) × K`,
래리 윌리엄스 변동성 돌파 원형과 동일. K=0.5도 표준값. 당일 청산(15:15 타임컷)도 원형의
데이 트레이딩 전제와 일치한다. **규칙을 잘못 넣은 것이 아니다.**

**② 유니버스 탓도 아니다.** §15.8은 후보 54종목으로 돌렸으나, 실제 paper 유니버스
20종목으로 재실행해도 거의 동일하다(PF 0.80→0.75, MDD 82.3→80.8%, 수익률 −78.45→−78.91%).

**③ 원인은 거래 마찰이다 — 비용 하향 스윕(`--backtest.mode=vb-cost-lab`)이 증명한다.**

| 왕복 비용 | 슬리피지(편도) | 트레이드 | 승률 | PF | 기대값 | 총수익 |
|---|---|---|---|---|---|---|
| 0.410% (현행 가정) | 0.100% | 3528 | 37.0% | 0.75 | −0.182% | −78.91% |
| 0.310% | 0.050% | 3982 | 38.4% | 0.84 | −0.125% | −67.53% |
| 0.250% | 0.020% | 4219 | 39.6% | 0.91 | −0.065% | −49.58% |
| **0.210%** (법정 바닥) | **0.000%** | 4297 | **41.1%** | **0.96** | **−0.025%** | −28.52% |

비용을 0.20%p 낮추자 기대값이 −0.182% → −0.025%로 거의 본전까지 올라오고, **승률이 37%→41%로
상승**한다(마찰이 작은 승리를 패배로 뒤집고 있었다는 직접 증거다). 즉 **VB의 원판 엣지는 대략
본전~미세 플러스이고, 마찰이 그것을 확실한 마이너스로 밀어낸다.**

**법정 바닥이 0.21%다.** 슬리피지를 0으로 놓아도 수수료 왕복 0.03% + **매도 제세 0.18%**가 남는다.
`BacktestCostProperties.setRoundTripCost()`가 그 아래를 거부하는 이유이며, 이 0.18%가 한국 주식
당일매매의 구조적 벽이다.

**④ 선물 전제라는 지적이 맞다.** 래리 윌리엄스는 이 기법을 **선물**(상품·지수선물)에서 만들었고,
선물은 (a) **매도 제세가 없고** (b) 수수료가 훨씬 낮으며 (c) **양방향(매수·매도)** 이다. 지수선물
왕복 비용은 0.02% 수준으로 **이 비용 모델로는 표현조차 불가능한 영역**이다. 위 추세를 외삽하면
그 비용대에서 기대값은 약 **+0.12~0.17%로 부호가 뒤집힌다**(다만 PF는 1.1~1.2 수준으로 추정돼
§4 기준 1.3에는 여전히 못 미칠 가능성이 크다). 우리 구현은 **매수 전용**이라 원형의 절반만 쓴다.

**결론**: B동의 실패는 "기법이 엉터리라서"가 아니라 **선물용 고빈도 기법을 한국 주식 당일매매로
옮겼기 때문**이다. 규칙을 고쳐서 해결할 문제가 아니다.

> **일반화 — 한국 주식에서는 매매 빈도 자체가 비용이다.**
> A동(돈치안)은 6.5년 **1,181건**, B동은 **3,528~4,297건**으로 약 3배 거래한다.
> 마찰은 거래 횟수에 비례하므로, 매도 제세 0.18%가 고정된 시장에서는 **덜 거래하는 전략이
> 구조적으로 유리하다.** §14에서 "출구를 다일 보유로 바꾸자 손익비가 뒤집혔다"는 발견도
> 같은 원인의 다른 얼굴이다.

## 16. 분봉 인프라 감사와 슬리피지 실측 설계 (2026-08-04)

§15.4에서 후보의 생사를 가르는 게 **비용 가정 0.41%**(여유 편도 0.045%p)로 드러나, 실측 경로인
분봉 인프라를 점검했다. 결과: **분봉은 한 건도 쌓이지 않았고, 쌓였더라도 검증에 닿을 수 없었다.**

### 16.2 이관 다리 — `--backtest.mode=import-minutes`

`MinuteCandleSource`(읽기 경계) + `JdbcMinuteCandleSource`(H2 `AUTO_SERVER`, **SELECT 전용**)
+ `MinuteCandleImporter`((종목,일자) 단위 멱등 이관). 운영 DB에는 **절대 쓰지 않는다** — 잔고·주문의
원본이기 때문이다. 실제 운영 DB 접속 검증은 분봉이 처음 쌓이는 날 이후로 미뤘다(장중에 실매매 DB로
접속을 시험할 이유가 없다).

### 16.3 슬리피지 실측 — 매매 경로를 건드리지 않는 쪽으로 결정

두 안을 놓고 비교했다:

| 안 | 방법 | 판정 |
|---|---|---|
| A. 주문 시점 기준가 기록 | `Signal`/`SizingResult`에 기준가를 실어 `OrderHistory`에 저장 | **기각** — 실매매 경로(인터페이스·주문 제출부)를 측정 목적으로 고쳐야 하고, `KisOrderClientImpl`엔 시세 접근이 없어 **주문 경로에 새 API 호출**이 생긴다. 사이징이 들고 있는 값은 *전일 종가*라 기준가로 못 쓴다(밤사이 갭) |
| **B. 분봉 + 기존 주문기록** | `OrderHistory`의 `requestedAt`이 속한 분봉 대 `filledPrice` 비교 | **채택** — 매매 코드 **무수정**, 과거 주문까지 소급 측정 |

B의 정밀도 우려(분 안에서 가격이 움직인다)는 **표본으로 상쇄된다**: 분 내 오차는 방향이 무작위라
평균에서 상쇄되고, 슬리피지는 항상 불리한 쪽으로 치우친 **계통 오차**라 남는다. 즉 주문 수백 건이면
평균 슬리피지를 0.045%p보다 훨씬 촘촘하게 가를 수 있다. 단건 정밀도가 아니라 평균이 필요한 문제다.

**전제**: 분봉 축적(2026-08-04 시작) + 그 기간의 실주문. 즉 **지금은 측정 불가이며, 데이터가 쌓이는
만큼만 앞당겨진다.**

### 16.4 분봉 시뮬레이터(스캘핑 재도전)의 정직한 일정

§13에서 기각된 스캘핑을 다시 다루려면 분봉 엔진이 필요한데, **막힌 것은 코드가 아니라 데이터다**:
축적이 오늘 시작이고, §15의 교훈상 **약세장을 포함하지 않은 표본으로는 합격 판정에 의미가 없다**.
따라서 분봉의 1차 용도는 스캘핑 신규 검증이 아니라 **§16.3 슬리피지 실측과 일봉 근사 교정**이며,
스캘핑 재도전은 그 뒤 순서다. (일봉 근사 자체가 §14~15 후보들의 공통 한계이므로, 교정만으로도
기존 판정의 신뢰도가 올라간다.)

### 16.5 슬리피지 1차 실측 (2026-08-07) — 매수는 관측, 매도는 측정 불가 (데이터 결함)

§16.3에서 채택한 방법(주문 시각의 분봉 대 체결가)으로 8/4~8/7 실주문을 대조했다.

**매수 11건 (분봉 매칭 성공분)**

| 항목 | 값 |
|---|---|
| 평균 슬리피지 | **−0.037%** (음수 = 불리하지 않음, 오히려 유리) |
| 범위 | −0.65% ~ +0.28% |
| 평균 절대값 | 0.169% |
| 백테스트 가정 | 편도 +0.100% (불리 방향) |

표면적으로는 **가정이 보수적**이라는 뜻이지만 **판정으로 쓸 수 없다**:
표본 11건, 표준오차 약 ±0.075%p — 0과도, 가정 0.1%와도 통계적으로 구분되지 않는다.

**⚠ 매도는 아예 측정할 수 없다 — 체결가가 0으로 기록된다.**

| 구분 | FILLED | 체결가 > 0 |
|---|---|---|
| 매수 | 25 | 25 |
| **매도** | **38 (전 기간)** | **1** |

매도 체결의 97%가 `filled_price = 0`이다. 체결 조회(VTTC8001R)가 모의 체결을 빈 응답으로
놓치고(로드맵 1.3 미해결 뿌리), `reconcileFilledFromBalance`의 "취소불가=체결" 복구 경로가
가격을 모르는 채 종결시키기 때문이다. **왕복 비용의 절반을 잴 수 없다.**

**부수 발견 — 칸별 성적 기록이 멈춰 있다.** `trade_result`는 전 기간 **5행(2026-07-30)** 뿐이고
그 이후 매도 27건에 대해 한 건도 쌓이지 않았다. 즉 ① 지갑 칸 실험의 방식별 성적 비교가
사실상 기록되지 않고 있으며 ② 칸 자산 = 배분금 + 실현손익 계산에서 실현손익이 항상 0이라
**칸 사이징 기준이 배분금에 고정**돼 있다.

**결론**: 슬리피지 판정은 **보류**. 로드맵 1.3(체결 추적 뿌리 수정)이 선행되어야 매도 체결가가
남고, 그래야 왕복 비용을 측정할 수 있다. 표본 수도 수백 건이 필요하다.
A동 후보의 "실측 슬리피지 확인" 관문은 **열리지 않았다.**

### 16.6 체결가 확보 진단 종결 (2026-08-10) — 모의투자에서는 매도 체결가를 얻을 수 없다

§16.5에서 매도 체결의 97%가 체결가 0으로 기록됨을 확인한 뒤, 로드맵 1.3 설계 노트의 가설
1~4를 실제로 검증했다(`BrokerFillHistoryClient` + `GET /api/trading/broker-fills`).

**가설 1·2(ODNO 필터 문제) — 기각.** 주문번호 필터를 제거하고 당일 전체를 조회해도 결과는
같았다. 하루 단위로 좁혀도 마찬가지다:

| 날짜 | 우리 DB 체결(매수/매도) | 브로커 조회(VTTC8001R) |
|---|---|---|
| 2026-08-04 | 9 / 8 | **0건** |
| 2026-08-05 | 8 / 11 | **0건** |
| 2026-08-06 | 8 / 7 | **0건** |
| 2026-08-07 | 0 / 1 | **0건** |

응답은 오류가 아니라 **정상(rt_cd=0)인데 내용이 비어 있다**(`apiError=false, count=0`).

**가설 4 확정 — 모의투자 환경 한정 결함.** 한국투자증권 모의투자에서 일별주문체결조회
(VTTC8001R)는 실제 체결이 있어도 빈 목록을 준다. 파라미터 문제가 아니다.

**과거분 복구는 불가능하다.** 되찾을 원본이 브로커 쪽에 조회되지 않는다. 잔고 조회는 매도한
종목이 사라져 가격이 없고, 분봉은 그 시각 *시장가*일 뿐 우리가 *체결받은 가격*이 아니다
(슬리피지는 정확히 그 차이라서 유도 불가). **2026-08-04~07 매도 27건의 슬리피지는 영구 미상.**

**남은 경로는 실시간 체결통보(WebSocket `H0STCNI9`)뿐이다** — 조회가 아니라 체결 순간에
브로커가 밀어주므로 조회 TR의 결함과 무관하고, 체결가·수량이 그 자리에서 온다. 다만 연결·
재접속·승인키가 붙는 큰 변경이라 설계 노트의 최후 수단(C안)이다.

> **§16.3 판정 변경 — "실측 슬리피지"는 모의투자에서 달성할 수 없는 관문이다.**
> 매수 쪽만 재봐야 왕복의 절반이고, 그마저 모의 체결가는 실제 시장 충격을 반영하지 않는다.
> 따라서 이 항목은 **실전 계좌 전환 이후로 이관**한다(설계 노트 B안). A동 승격 조건에서
> 이 관문을 그대로 두면 영원히 열리지 않는다 — ADR-001 개정 §2.1 단서도 함께 수정했다.

**부수 소득**: 진단 과정에서 ODNO 필터를 제거한 것은 되돌리지 않는다. 원인은 아니었으나
체결조회 호출이 "대기 주문 N개마다 3초 주기로 N번"에서 "주기당 1번"으로 줄어, 모의 유량
(1건/초) 압박이 크게 완화되기 때문이다.
