# 성과 거버넌스 — 지속적으로 돈을 못 벌 때의 대응 정책

> 이 앱의 목적은 트레이딩으로 돈을 버는 것이다. 따라서 "못 벌고 있다"를 어떻게 판정하고,
> 판정되면 무엇을 할지를 **미리, 규칙으로** 정해 둔다. 손실이 난 뒤에 정하면 반드시
> 감정(본전 심리, 매몰비용)이 개입하기 때문이다. 이 문서의 규칙은 손실 상황에서
> 재량으로 완화할 수 없으며, 개정은 손실 구간이 아닐 때만 한다.

비유하면 이것은 **프로야구의 1군/2군 시스템**이다. 성적이 떨어진 선수(전략)를
감으로 빼는 게 아니라, 타율(지표)·부진 기간(평가 창)이 기준을 넘으면 2군(모의투자)으로
강등하고, 2군에서 성적을 증명해야 1군(실전)으로 복귀시키며, 그래도 안 되면 방출(폐기)한다.

---

## 1. "돈을 번다"의 정의 — 판정 기준선

성과는 반드시 **모든 비용 차감 후** 기준으로 판정한다:

```
순손익 = 매매손익 − 위탁수수료 − 증권거래세(매도) − 슬리피지(체결가 − 신호 시점가)
```

그리고 "벌었다"의 비교 대상(허들)은 0이 아니다:

| 허들 | 기준 | 의미 |
|---|---|---|
| 최소 허들 | **무위험 수익률** (CMA/예금 금리, 연 ~3%) | 이걸 못 넘으면 트레이딩할 이유가 없음 |
| 목표 허들 | **월 3% (연 복리 환산 약 42.6%)** — 2026-07-21 사용자 확정 | MDD를 감수하는 대가. ⚠ 이 수치는 목표일 뿐, 백테스트 합격 기준(BACKTEST-DESIGN.md §4: PF≥1.3·MDD≤15% 등)을 낮추는 근거로 쓰지 않는다 — 목표 달성은 검증된 전략의 존재를 전제한다 |
| 참고 지표 | KOSPI 수익률 | 시장을 사기만 해도 얻는 수익과 비교 |

> 슬리피지 측정을 위해 **신호 발생 시점 가격과 실제 체결가를 모두 기록**해야 한다
> (Phase 2 구현 항목 — order_history에 signal_price 컬럼 추가).

**비용 상수 관리**: 위탁수수료율·거래세율은 코드가 아니라 설정 파일(`trading-costs.yml`)로
관리하고, 값은 실전 계좌 개설 시 실측으로 확정한다 (세율은 개정되므로 연 1회 점검).
슬리피지는 상수가 아니라 **실측치**(체결가 − 신호시점가)의 누적 통계로 관리하며,
백테스트의 슬리피지 가정값([백테스트 설계 §2.3](BACKTEST-DESIGN.md))을 이 실측으로 교정한다.

## 2. 측정 지표와 평가 주기

| 지표 | 정의 | 판정 용도 |
|---|---|---|
| **기대값 (Expectancy)** | (승률 × 평균이익) − (패률 × 평균손실), 트레이드당 | 전략이 구조적으로 +인지의 핵심 지표 |
| Profit Factor | 총이익 ÷ 총손실 | 1.0 미만 = 구조적 손실 |
| MDD | 전고점 대비 최대 낙폭 | 백테스트 대비 괴리 감시 |
| 실전-백테스트 괴리 | 실전 기대값 ÷ 백테스트 기대값 | 슬리피지/구현 오류 탐지 |
| 연속 손실 | 최대 연속 패 횟수 | 통계적 이상 감지 |

**평가 주기**: 주간(모니터링용 리포트) + 월간(강등/승격 판정). 판정은 월간에만 한다.

**최소 표본 원칙**: 트레이드 **30건 미만**에서는 성과 판정을 유보한다.
동전도 10번 던지면 7:3이 흔하다 — 소표본으로 전략을 죽이는 것도, 살리는 것도 노이즈에
속는 것이다. 단, §4의 **하드 리스크 한도는 표본 수와 무관하게 즉시 발동**한다
(성과 판정과 생존 한도는 다른 층위다).

## 3. 전략 상태 머신 — 5단계 신호등

전략(현재는 VolatilityBreakout 1개, 이후 전략별 독립 적용)은 항상 아래 중 한 상태에 있다:

```
NORMAL ──▶ WATCH ──▶ DE_RISKED ──▶ PAPER_ONLY ──▶ RETIRED
  ▲          │           │             │
  └──────────┴───────────┴─── 복귀 조건 충족 시 (§5)
```

| 상태 | 의미 | 자금 |
|---|---|---|
| `NORMAL` | 정상 운용 | 배정 자금 100% (Sleeve B 기준 총자산 30% 한도) |
| `WATCH` | 부진 관찰 — 매매는 유지, 리포트 주기 주간→일간 강화 | 100% 유지 |
| `DE_RISKED` | 자금 축소 운용 | **50%로 축소** |
| `PAPER_ONLY` | 실전 중단, 모의투자로 강등 (신호·기록은 계속) | 실전 0% |
| `RETIRED` | 전략 폐기 — 코드는 보존, 재활성화는 신규 전략 승인 절차로만 | 0% |

## 4. 강등 트리거 (정량 — 월간 판정, 하나라도 해당 시 강등)

### NORMAL → WATCH
- 롤링 20 트레이드 기대값 < 0, 또는
- 월간 순손익 2개월 연속 마이너스, 또는
- 실전-백테스트 괴리: 실전 기대값이 백테스트의 50% 미만

### WATCH → DE_RISKED
- WATCH 진입 후 다음 월간 판정에서도 WATCH 조건 해당 (개선 없음), 또는
- 3개월 연속 월간 순손익 마이너스

### DE_RISKED → PAPER_ONLY
- 실전 MDD가 **백테스트 MDD의 1.5배** 초과 (전략이 백테스트와 다른 세상에 있다는 증거), 또는
- 6개월 누적 순손익 마이너스, 또는
- DE_RISKED 진입 후 2개월 연속 개선 없음

### PAPER_ONLY → RETIRED
- 모의 재검증(§5) 2회 연속 실패, 또는
- 부진 원인 진단(§6) 결과 "알파 소멸" 판정

### 즉시 발동 (월간 판정 대기 없음 — 표본 수 무관)
- `GlobalEquityStopRule` MDD 10% 도달 → 기존대로 강제청산 + `EMERGENCY_STOPPED`,
  재가동은 본 문서 §6 원인 진단을 통과해야만 가능
- 시스템 결함 발견 (주문 오류, 데이터 오염) → 즉시 `PAPER_ONLY`, 수정 후 재검증

## 5. 복귀(승격) 조건 — 강등보다 어렵게

복귀 기준을 강등 기준보다 엄격하게 두는 것이 원칙이다 (재진입 비용 < 재손실 비용).

| 승격 | 조건 |
|---|---|
| PAPER_ONLY → DE_RISKED | 모의에서 **30 트레이드 이상 + 할인 후 기대값 > 0 + Profit Factor ≥ 1.3** |
| DE_RISKED → NORMAL | 실전 축소 자금으로 2개월 연속 순이익 + 백테스트 괴리 정상화 |
| WATCH → NORMAL | 다음 월간 판정에서 WATCH 조건 전부 해소 |

복귀는 단계를 건너뛸 수 없다 (PAPER에서 바로 NORMAL 불가).

**모의투자 성과 할인**: KIS 모의는 슬리피지·호가 잔량이 반영되지 않아 체결이
구조적으로 낙관적이다. 따라서 승격 판정 시 **모의 기대값에 30% 할인을 적용한 값**이
기준을 넘어야 한다 (예: 모의 기대값 +1.0%면 +0.7%로 간주). 할인율은 실전 데이터가
쌓이면 실측 괴리(§2의 실전-백테스트 괴리와 동일 방식)로 교정한다.

## 6. 부진 원인 진단 — 강등 시 필수 체크리스트

강등이 발생하면 "왜"를 4개 범주로 진단하고 기록한다. 처방이 다르기 때문:

| 원인 | 증상 | 처방 |
|---|---|---|
| **① 구현 버그** | 백테스트와 신호 자체가 다름, 주문/체결 오류 | 코드 수정 → 모의 재검증. 전략 잘못이 아님 |
| **② 비용 잠식** | 신호는 맞는데 수수료+세금+슬리피지가 엣지보다 큼 | 매매 빈도 축소, 지정가 전환, 최소 기대수익 필터 상향 |
| **③ 레짐 변화** | 특정 시장 국면(횡보장 등)에서만 손실 집중 | 레짐 필터 추가 (예: 지수 추세 하락 시 휴면) — 단, 백테스트 재검증 필수 |
| **④ 알파 소멸** | 전 구간에 걸쳐 기대값이 서서히 0으로 수렴 | **폐기**. 파라미터 재최적화로 되살리려는 시도는 과최적화 — 금지 |

> **금지 사항**: 손실 구간에서 K값 등 파라미터를 "조금만 바꿔보는" 행위.
> 이는 데이터에 맞춰 곡선을 구부리는 것(과최적화)이며, 변경은 반드시
> ①~③ 진단 근거 + Walk-Forward 재검증을 거쳐 PAPER_ONLY 상태에서만 한다.

## 7. 프로젝트 수준의 자본 규칙 — 손실 예산과 이익 처리

### 7.1 손실 예산 (수업료)

전략 단위가 아니라 **프로젝트 전체**의 손실 한도를 정한다:

- **총 손실 예산: 초기 투입 자본의 15%** (실전 전환 시점에 금액으로 확정)
- 예산 소진 시: 전체 실전 운용 **무기한 중단** → 전면 회고(전 트레이드 분석 리포트 작성)
  → 재개하려면 새 백테스트 + 모의 6개월 재검증을 처음부터
- 이 예산은 "시장에서 배우는 수업료"다. 예산 안에서의 손실은 실패가 아니라 데이터이고,
  예산을 넘기는 순간부터는 학습이 아니라 소모다.

### 7.2 이익 처리 — 벌었을 때의 규칙도 미리 정한다

손실 규칙만 있고 이익 규칙이 없으면, 수익 구간에서 재량(욕심)이 개입한다:

- **반기 정산**: 6개월마다 누적 순이익의 **50%는 인출**(증권 계좌 밖으로), 50%는 재투자.
  인출분은 이 시스템의 성과가 "실현된 현실"임을 확인하는 장치다 — 계좌 숫자는
  다음 하락에 사라질 수 있지만 인출된 돈은 사라지지 않는다.
- **복리 상한**: 재투자로 운용 자본이 커지면 1R(계좌 1%)의 절대액도 커진다.
  운용 자본이 **초기 자본의 2배**에 도달하면 증액을 멈추고 초과분은 전액 인출한다.
  전략의 검증된 용량(capacity)을 넘는 자본은 슬리피지만 키운다.
- **증액 금지 조건**: WATCH 이하 상태이거나 손실 예산의 절반 이상을 소진한 상태에서는
  외부 자금 추가 투입을 금지한다 (물타기의 시스템 버전을 차단).

## 8. 시스템 구현 매핑 (기존 코드와의 연결)

| 구현 항목 | 위치/방식 | 단계 |
|---|---|---|
| 트레이드별 순손익·슬리피지 기록 | `order_history`에 signal_price·수수료·세금 컬럼, 체결 시 계산 | Phase 2 |
| 성과 지표 집계 (기대값·PF·MDD·연속손실) | `PerformanceReporter` 신설 — 주간/월간 텔레그램 리포트 | Phase 2 |
| 전략 상태 머신 | `StrategyStatus` (NORMAL~RETIRED) — `TradingStatusManager`와 별개 (전자는 전략 성과, 후자는 계좌 안전) | Phase 3 |
| 강등 자동화 | 월간 판정 스케줄러 — WATCH/DE_RISKED 전환은 자동, PAPER/RETIRED 전환은 **알림 후 사람 승인** | Phase 3 |
| DE_RISKED 자금 축소 | R 기반 사이징(방법론 §4.3)의 R을 절반으로 | Phase 2 사이징 구현에 포함 |
| 백테스트 기준선 저장 | 전략별 기대값·MDD를 설정 파일로 버전 관리 — 괴리 판정의 분모 | Phase 3c |

> 주의: 강등 판정 자체를 완전 자동화하되, **폐기(RETIRED)만은 사람이 승인**한다.
> 반대로 **완화(승격)는 어떤 경우에도 수동 재량으로 앞당기지 않는다** — 비대칭이 의도다.
