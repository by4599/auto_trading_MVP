## 방법
- 실제 실행 중인 모의 앱(8080)을 Playwright로 열어 탭 6개 × PC(1280px)·휴대폰(375px) 캡처 + 자동 측정. 화면 열람만 했다 — API는 GET만 허용하고
  POST 등은 막아 매매 버튼이 눌릴 수 없게 했다. 캡처는 스크래치 폴더 `ui/desk-*.png`·`ui/mob-*.png`(저장소 밖).

- 스킬 추천 중 **맞지 않아 버린 것**: 패턴 "Enterprise Gateway"(영업용 랜딩 페이지 구조 — 대시보드와 무관), "초록 = 이익"(한국 관례는 빨강 = 이익),
  Google Fonts 외부 글꼴(로컬 운영 도구 — 외부 의존 추가 안 함). 채택: 다크 OLED 계열 유지, 고밀도 간격, 이모지 아이콘 금지, 포커스 표시, 375/768/1024/1440 반응형.

## 고칠 순서 제안 (정적 리소스만, 매매 경로 무변경)
1. **안전·휴대폰**: 정지·재개·시작·원복에 확인 창(원복은 "낙폭 한도 8% → 10%" 경고 포함), 머리줄·탭 줄바꿈과 가로 넘침 해소(표는 가로 스크롤 상자), 포커스 표시 복구.
2. **결론 먼저**: 홈 맨 위 요약 카드 — 오늘·누적 손익, 운전 상태, "왜 안 사고 있나"(차단 사유 1위를 쉬운 말로). 매도가 0원 칸에 "모의 결함 — 실제 손익은 실적 탭" 표시, 종목명 함께.
3. **정리**: 글자 최소 12px, 색 변수화(빨강 = 이익/매수, 파랑 = 손실/매도, 위험은 별도 주황), 실적 기록 접기, 이모지 → SVG, 낡은 문구.
- 300줄 초과 파일(`core.js` 522 · `tab-home.js` 483 · `app.css` 579)은 손대는 김에 책임 단위로 나눈다. 적용 후 같은 캡처·측정을 다시 돌려 전후 비교. 반영에는 앱 재시작 필요(사람).
