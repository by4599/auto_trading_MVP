## 1. 근거 요지
1. **제한이 실제로 걸린다**: 뉴스 3s/10s(`NewsAggregatorService.java:63-67`), DART 5s/30s(`HttpDartApiClient.java:47-50`). 정적 `RestClient.builder()`라
   부트 설정이 덮지 못한다. spring-web 6.1.14: `initRequestFactory`는 명시 팩토리를 그대로 쓰고, 없으면 HttpComponents→Jetty→JDK→Simple(42 판단 확인).
   DART 세 호출(corpCode·list.json·document.xml) 모두 같은 클라이언트. 읽기 제한은 바이트 사이 침묵 기준 — 큰 다운로드를 끊지 않는다.
   운영 코드에 팩토리 없는 `RestClient` 0개.
2. **fixedDelay — 부작용 없음, 이득**: 첫 실행 그대로(뉴스 즉시, 공시 2분 뒤). 간격은 실행 시간만큼 밀린다(평소 수 초). 절전 복귀 시 1번만 —
   DART 호출 한도에도 유리. B-4 표본 누락 위험은 늘지 않는다(매번 최근 7일 재조회 + 접수번호 중복 제거).
3. **하트비트 전용 스레드 — 타당**: 트리거는 기본 스레드(`DeadmanHeartbeat.java:87`, `ScheduledPlacementTest:58` 고정). 1스레드·대기 2건·오래된 것 버림이
   맞다(절전 복귀 몰아치기 때 최대 3건). `@PreDestroy`는 `ExecutorService`만 닫고 공유 `ThreadPoolTaskScheduler`는 `ExecutorService`가 아니라 안전.
   이름표 없는 Executor 주입·`@Async` 0건 — Executor 빈 2개 환경의 모호성 위험은 오히려 줄었다.
4. **토큰 가림 — 충분**: 정규식 `bot\d+:[A-Za-z0-9_-]+`가 실제 운영 토큰 전체를 덮는다(값 미출력). 9-08 줄에 적용하면 남는 토큰 0.
   4xx/5xx 예외 메시지엔 URL이 없고, I/O 오류 메시지엔 URL의 `?` 앞까지만(DART 키는 원래 빠짐). 다른 로그 줄·넘침 WARN엔 본문만, DEBUG 요청 로그 꺼짐.
   전수: 로그 113개 파일에서 토큰 패턴은 9-08 1줄뿐, git 전체 이력 0건, 테스트 토큰은 가짜. 참고: 구현 기록의 "원인 메시지에도 같은 URL"은 실제와 다르다
   (9-08 원인 `SocketTimeoutException`엔 URL 없음) — 가림이 양쪽을 덮어 결과는 같다.
5. 흐름·프로필·크기 위반 없음(운영 최대 238줄, 함수 최대 40줄). 결과 XML 1010/1010, 대상 스위트 18/18 + ScheduledPlacement 2/2 — XML이 코드보다 나중(19:34:47 > 19:33:59).
